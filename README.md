# NextIDE

NextIDE is a local-first, capability-oriented coding IDE.

## Workspace status

The repository currently contains the first Phase 0 vertical slice:

- Rust workspace
- transactional document model
- undo/redo
- snapshot/recovery primitives
- minimal CLI smoke path
- headless Desktop Shell with window, input, command-palette, notification, and file-tree pipelines
- incremental file-tree rendering with structured change batches and events
- task runtime with lifecycle events, summaries, cancellation, timeout, cleanup, and task queries
- VFS read-only, typed file metadata queries (`exists` returning `io::Result<bool>` plus `is_file`/`is_dir`/`metadata` returning `FileKind` + `FileMetadata` with kind/len/readonly): `exists` reports `Ok(true)` for existing entries and `Ok(false)` for missing ones, and rooted filesystems reject path escapes with `Err(PermissionDenied)` instead of silently reporting `false`; missing entries report `Ok(false)` from `exists`/`is_file`/`is_dir` and `NotFound` from `metadata`
- VFS typed, stable-sorted directory enumeration (`read_dir` returning `io::Result<Vec<FileEntry>>` with name/path/kind/len): entries sort by name in stable order, missing paths report `NotFound`, non-directory paths report `NotADirectory`, and root escapes keep reporting `PermissionDenied`; the trait default returns `Unsupported`, so existing `FileSystem` implementations (`LocalFileSystem`, `MemoryFs`, `TreeFs`, `NoopFs`) compile and behave unchanged, and `LocalFileSystem::list` now delegates to `read_dir`
- dependency-free workspace text search (`search` module: `SearchQuery`/`SearchOptions`/`SearchMatch`/`SearchMatcher`, entry points `search::search(fs, &query)` and `query.run(&fs)`): recursively walks `read_dir` over any rooted `FileSystem`, reports every matching line (relative path, 1-based line, byte column, line text), skips binary (invalid UTF-8 or NUL-containing) and unreadable/denied files and subdirectories silently, propagates only search-root errors, stably sorts results by `(path, line, column)`, and truncates to `max_results`; `case_sensitive` (default on), `max_depth` (default 64) and a normalized `"."` root keep paths inside the workspace root and walks finite even through symlinked cycles; matching is pluggable through the reusable `SearchMatcher` — `SearchQuery::new` keeps the plain literal-substring behavior, while `SearchQuery::glob` (or `matcher: SearchMatcher::Glob`) interprets the needle as a simple glob pattern (`*` = any run of characters, `?` = exactly one character), a deliberately non-regex wildcard matcher with no character classes, alternation, anchors, or escapes
- minimal, dependency-free Git status capability (`git` module: `GitStatusEntry`/`GitFileState`/`GitStatusCode`/`GitStatusSnapshot`, entry point `git::status(root) -> io::Result<GitStatusSnapshot>`): runs `git -C <root> status --porcelain=v1` through `std::process::Command` (no shell, the root is a single argument), parses every XY status code (`M`/`T`/`A`/`D`/`R`/`C`/`U`/`?`/`!`, unknown codes preserved as `Unknown`), keeps rename/copy pairs as `path` (current) plus `original` (source), decodes git's C-style quoted paths (`"with space \344\270\255\346\226\207.txt"` → `with space 中文.txt`), and returns entries stably sorted by path; root safety: the root must exist (`NotFound`) and be a directory (`NotADirectory`), a missing `git` binary surfaces as `NotFound`, a non-zero git exit (e.g. "not a git repository") surfaces as `Other` with git's stderr in the message, and any parsed path that is absolute or contains a `..` component is rejected with `InvalidData` so a snapshot can never name a path outside the repository; per porcelain v1 semantics paths are relative to the repository top level, so when `root` is the repository top level (the normal workspace case) every reported path is relative to `root` exactly
- minimal Git diff query (`git` module: `GitDiffLine`/`GitDiffLineKind`/`GitDiffHunk`/`GitDiffFile`/`GitDiffSnapshot`, entry point `git::diff(root, path: Option<&Path>) -> io::Result<GitDiffSnapshot>`): runs `git -C <root> diff --no-ext-diff --unified=3` (worktree vs index, no external diff driver, 3 context lines), parses the unified output into files sorted stably by path, each with its hunks and lines (`GitDiffLine` records context/added/removed kind, 1-based old/new line numbers, and the line text; `GitDiffFile` carries the current `b/` path — decoded from git's C-style quoting — plus a `binary` flag for `Binary files ... differ` entries, which carry no hunks); the optional `path` is passed to git as a pathspec after `--` and must be rooted at `root` — relative, non-empty, and free of `..`, root and drive components, otherwise `InvalidInput` before git is spawned; root/exit/parse error behaviour matches `status` (`NotFound`/`NotADirectory`/`Other` with git's stderr/`InvalidData`), and because plain `git diff` exits 0 whether or not differences exist, a non-zero exit always means a real failure; unlike porcelain, diff line *content* is not UTF-8 validated — invalid bytes become U+FFFD (git quotes paths but never content) — while every parsed path still passes the same escape-rejecting safety check as `status`
- minimal Git stage and commit capability (`git` module: `git::stage(root, paths: &[&Path]) -> io::Result<GitStatusSnapshot>` and `git::commit(root, message) -> io::Result<GitCommitResult>`, with `GitCommitResult { hash, summary }` where `hash` is the full 40-character object id read back via `git rev-parse HEAD` and `summary` is the git-defined subject via `git log -1 --format=%s`): `stage` runs `git -C <root> add -- <paths>` (no shell; every path is its own argument after the `--` separator, so option-like names such as `--help`/`-f` are staged literally) and returns the fresh `GitStatusSnapshot` from `git::status`; every stage path is validated before git is spawned — non-empty, relative, free of `..`/root/drive components, and not `:`-prefixed (git pathspec magic such as `:(top)`/`:(exclude)`) — and an empty `paths` slice is rejected, all with `InvalidInput`; `commit` rejects empty/whitespace-only messages and NUL bytes with `InvalidInput` before spawning and runs `git -C <root> commit --message=<message>` (the message is a single argument, never shell-interpreted, so `--amend`-looking text is committed verbatim); error behaviour matches `status`/`diff` (`NotFound`/`NotADirectory`/`Other` with git's message — taken from stderr, falling back to stdout, because `git commit` prints failures like "nothing to commit" there), and existing `status`/`diff` behaviour is unchanged
- minimal safe Git unstage capability (`git` module: `git::unstage(root, paths: &[&Path]) -> io::Result<GitStatusSnapshot>`): runs `git -C <root> reset -- <paths>` (no shell; every path is its own argument after the `--` separator, so option-like names such as `--help`/`-f` are un-staged literally) and returns the fresh `GitStatusSnapshot` from `git::status`; every path is validated before git is spawned with the same rules as `stage` — non-empty, relative, free of `..`/root/drive components, and not `:`-prefixed (git pathspec magic) — an empty `paths` slice is rejected, all with `InvalidInput`, and a `.` pathspec un-stages everything under `root`; unlike `git add`, a `git reset` pathspec that matches nothing is a no-op (exit 0), so un-staging a path that is not staged (or does not exist) succeeds and the returned snapshot always reflects the resulting state; error behaviour matches `status`/`diff`/`stage`/`commit` (`NotFound`/`NotADirectory`/`Other` with git's message), and existing `status`/`diff`/`stage`/`commit` behaviour is unchanged
- minimal safe Git branch query and checkout capability (`git` module: `GitBranch`/`GitBranchSnapshot`, entry points `git::branches(root) -> io::Result<GitBranchSnapshot>` and `git::checkout(root, branch) -> io::Result<GitStatusSnapshot>`): `branches` runs `git -C <root> for-each-ref --format=%(HEAD)|%(refname:short) refs/heads` (no shell; git's own machine-oriented `%(HEAD)` atom emits `*` for the checked-out branch and a space otherwise, and names are split on the first `|`, so no human-format parsing is involved) and returns every local branch stably sorted by short name, each as a `GitBranch { name, current }` — a detached HEAD marks no branch as current, and every parsed name still passes the same escape-rejecting check as status paths; `checkout` validates the branch name before spawning — non-empty, free of NUL bytes, not absolute and without `..` components, and not `-`-prefixed, so it can never be parsed as a git option (`--` cannot shield it because `git checkout --` turns the argument into a pathspec instead of a branch) — then runs `git -C <root> checkout <branch>` with the name as a single argument and returns the fresh `GitStatusSnapshot` from `git::status`; error behaviour matches `status`/`diff`/`stage`/`commit` (`NotFound`/`NotADirectory`/`InvalidInput`/`Other` with git's message), and existing `status`/`diff`/`stage`/`commit` behaviour is unchanged
- minimal safe Git restore and stash capability (`git` module: entry points `git::restore(root, paths: &[&Path]) -> io::Result<GitStatusSnapshot>` and `git::stash_push(root, message: Option<&str>) -> io::Result<GitStatusSnapshot>`): `restore` discards the named paths' *worktree* changes with `git -C <root> restore -- <paths>` (no shell; every path is its own argument after the `--` separator and validated exactly like stage/unstage paths — non-empty, rooted at `root`, not `:`-prefixed — so option-like names such as `--help`/`-f` are restored literally, and an empty `paths` slice is rejected with `InvalidInput`); `git restore` writes the worktree from the index by default, so staged changes are kept, untracked files are never deleted (a pathspec matching an untracked file is a git error surfaced as `Other`), and unstaged deletions are re-created; `stash_push` moves the repository's *tracked* changes (staged and unstaged) into a new stash entry with `git -C <root> stash push [--message=<message>]` — the optional message follows the commit rules (non-empty after trimming, no NUL bytes, else `InvalidInput`) and travels as a single `--message=<message>` argument so `--amend`-looking text is recorded verbatim — and a stash push with nothing to stash is a no-op (git exits 0 with "No local changes to save"), while untracked files are never stashed; both return the fresh `GitStatusSnapshot` from `git::status`, and the module docs document the dangerous-operation boundaries: `restore` is destructive and irreversible (a `.` pathspec discards every unstaged change under `root`), and `stash_push` rewrites the whole repository's worktree — from a nested `root` it also stashes changes outside `root`, and stash entries are recoverable via `git::stash_apply`/`git::stash_pop` (see the stash-management bullet below); error behaviour matches the other operations (`NotFound`/`NotADirectory`/`InvalidInput`/`Other` with git's message), and existing `status`/`diff`/`stage`/`unstage`/`commit`/`branches`/`checkout` behaviour is unchanged
- minimal safe Git stash management (`git` module: `GitStashEntry`/`GitStashSnapshot`, entry points `git::stash_list(root) -> io::Result<GitStashSnapshot>`, `git::stash_apply(root, index: usize) -> io::Result<GitStatusSnapshot>` and `git::stash_drop(root, index: usize) -> io::Result<GitStatusSnapshot>`): `stash_list` runs `git -C <root> stash list` (no shell) and parses each `stash@{N}: <description>` line into a typed entry — the entry's `index` (the `stash@{N}` ref number, 0 = most recent) and its `description` (the text after the prefix: the recorded message for entries created by `stash_push`, otherwise git's default `WIP on <branch>: <abbrev> <subject>` line) — stably sorted by index ascending, with malformed lines rejected as `InvalidData`; `stash_apply` runs `git -C <root> stash apply stash@{index}` where the ref is formatted from the caller-supplied index into a single argument (never parsed as an option), and before git is spawned the index is validated against a fresh `stash_list`, so an out-of-range index is `InvalidInput` instead of a git error; a successful apply *keeps* the entry (unlike `git stash pop`), and plain `git stash apply` (no `--index`) restores the changes into the worktree without reinstating the staged/unstaged split; `stash_drop` runs `git -C <root> stash drop stash@{index}` with the same index validation and permanently deletes the entry (git renumbers the rest); both return the fresh `GitStatusSnapshot` from `git::status`; error behaviour matches the other operations (`NotFound`/`NotADirectory`/`InvalidInput`/`Other` with git's message — an apply that conflicts with the current worktree leaves conflict markers and fails with `Other` — /`InvalidData`), and existing `status`/`diff`/`stage`/`unstage`/`commit`/`branches`/`checkout`/`restore`/`stash_push` behaviour is unchanged
- minimal safe Git stash pop capability (`git` module: `git::stash_pop(root, index: usize) -> io::Result<GitStatusSnapshot>`): applies entry `stash@{index}` with `git -C <root> stash pop stash@{index}` (no shell; the ref is formatted from the caller-supplied index into a single argument, so it can never be parsed as an option) and drops it on success — git's own apply-plus-drop safety: the entry is removed only after a successful apply, so a pop that conflicts with the current worktree fails with `Other` carrying git's message and leaves the entry in place (with conflict markers in the worktree), never silently deleting a stash; the index is validated against a fresh `stash_list` before git is spawned exactly like `stash_apply`/`stash_drop`, so an out-of-range index is `InvalidInput` instead of a git error; on success the entry is dropped (git renumbers the rest) and the changes are restored into the worktree without reinstating the staged/unstaged split, like plain `stash_apply`; returns the fresh `GitStatusSnapshot` from `git::status`; error behaviour matches the other operations (`NotFound`/`NotADirectory`/`InvalidInput`/`Other` with git's message/`InvalidData`), and existing `status`/`diff`/`stage`/`unstage`/`commit`/`branches`/`checkout`/`restore`/`stash_push`/`stash_list`/`stash_apply`/`stash_drop` behaviour is unchanged
- minimal safe Git commit amend capability (`git` module: `git::amend(root, message) -> io::Result<GitCommitResult>`): replaces the current HEAD commit with `git -C <root> commit --amend --message=<message>` (no shell; the message is a single `--message=<message>` argument exactly like `commit`, so option-like text such as `--amend` is recorded verbatim) and returns the same `GitCommitResult` as `commit` — the fresh HEAD hash via `git rev-parse HEAD` and the git-defined subject via `git log -1 --format=%s` — reusing `commit`'s message validation (empty/whitespace-only or NUL messages are `InvalidInput` before git is spawned) and its result parsing; the amend never opens an editor and rewrites the last commit in place (the parent is kept, staged changes are folded in, the hash always changes), so it is a history rewrite that must only be applied to commits that have not been published; error behaviour matches `commit` (`NotFound`/`NotADirectory`/`InvalidInput`/`Other` with git's message, e.g. "You have nothing to amend." for a repository without commits), and existing `status`/`diff`/`stage`/`unstage`/`commit`/`branches`/`checkout`/`restore`/`stash_push`/`stash_list`/`stash_apply`/`stash_drop`/`stash_pop` behaviour is unchanged
- minimal safe Git history query (`git` module: `GitCommitEntry`/`GitLogSnapshot`, entry point `git::log(root, limit: Option<usize>) -> io::Result<GitLogSnapshot>`): runs `git -C <root> log --format=%H%x00%P%x00%an%x00%aI%x00%s --date=iso-strict` (no shell; fields are NUL-separated by git itself and records are newline-terminated, so parsing is machine-oriented) and returns each commit as a `GitCommitEntry { hash, parents, author, date, subject }` in git's own output order — newest commit first, never re-sorted — where `parents` is empty for a root commit and holds one hash per parent for a merge; `limit` caps the query itself (`--max-count=n`) and the snapshot, `Some(0)` short-circuits to an empty snapshot without spawning git, and `None` returns the whole history; parsed output is validated before it is trusted — the output must be valid UTF-8, every record must have exactly the five fields with a non-empty author and date, and every hash (commit and parent) must be non-empty hexadecimal, otherwise `InvalidData`; root/exit error behaviour matches `status` (`NotFound`/`NotADirectory`/`Other` with git's message — a repository without any commits makes `git log` itself fail with "does not have any commits yet"), and existing `status`/`diff`/`stage`/`unstage`/`commit`/`branches`/`checkout`/`restore`/`stash_push`/`stash_list`/`stash_apply`/`stash_drop`/`stash_pop`/`amend` behaviour is unchanged
- minimal safe Git tag query (`git` module: `GitTag`/`GitTagSnapshot`, entry point `git::tags(root) -> io::Result<GitTagSnapshot>`): runs `git -C <root> for-each-ref --format=%(objectname)%00%(refname:short) refs/tags` (no shell; git's own machine-oriented output — NUL-separated fields, newline-terminated records) and returns every tag stably sorted by short name, each as a `GitTag { name, object }` where `object` is the full object id git reports — for a lightweight tag the id of the object it names (typically a commit), for an annotated tag the id of the tag object itself, recorded without expanding the tag to its target; parsed output is validated before it is trusted — valid UTF-8, exactly two fields per record, a non-empty hexadecimal object, and a non-empty name that passes the same escape-rejecting check as status paths, otherwise `InvalidData`; error behaviour matches `status`/`branches` (`NotFound`/`NotADirectory`/`Other` with git's message), and existing `status`/`diff`/`stage`/`unstage`/`commit`/`branches`/`checkout`/`restore`/`stash_push`/`stash_list`/`stash_apply`/`stash_drop`/`stash_pop`/`amend`/`log` behaviour is unchanged
- minimal safe Git tag create/delete capability (`git` module: entry points `git::tag(root, name) -> io::Result<GitTagSnapshot>` and `git::delete_tag(root, name) -> io::Result<GitTagSnapshot>`): `tag` creates a *lightweight* tag with `git -C <root> tag -- <name>` (no shell; the name is a single argument and the `--` separator shields it from option parsing) and `delete_tag` removes a tag with `git -C <root> tag --delete <name>`; both return the fresh `GitTagSnapshot` from `git::tags`, and both are strictly local — the worktree and the index are never touched; every name is validated before git is spawned — non-empty, free of NUL bytes, not `-`-prefixed, relative and free of `..` and empty components (no leading, trailing or doubled `/`), and free of control characters, whitespace and git's other ref-forbidden characters (`~`, `^`, `:`, `?`, `*`, `[`, `\`, `@{`, leading-dot components, `.lock`-suffixed components, trailing dots) — mirroring `git check-ref-format` while allowing one-level names such as `v1.2` and slash names such as `feature/v1.2`; error behaviour matches the other operations (`NotFound`/`NotADirectory`/`InvalidInput`/`Other` with git's message — an existing tag for `tag`, an unknown tag for `delete_tag` —/`InvalidData`), and existing `status`/`diff`/`stage`/`unstage`/`commit`/`branches`/`checkout`/`restore`/`stash_push`/`stash_list`/`stash_apply`/`stash_drop`/`stash_pop`/`amend`/`log`/`tags`/`remotes` behaviour is unchanged
- minimal read-only Git remote query (`git` module: `GitRemote`/`GitRemoteSnapshot`, entry point `git::remotes(root) -> io::Result<GitRemoteSnapshot>`): runs `git -C <root> remote -v` (no shell) and is strictly read-only — it only reads the local Git configuration, never contacts a network and never fetches or pushes; git's own machine-oriented `name<TAB>url (fetch|push)` lines are parsed into one `GitRemote { name, fetch_url, push_urls }` per remote — `fetch_url` from the `(fetch)` line (`remote.<name>.url`, `None` when the remote has no fetch URL, in which case git prints a bare `name<TAB>` line) and `push_urls` from the `(push)` lines in git's order (a remote without an explicit `remote.<name>.pushurl` reports its fetch URL as the single push URL, and a multi-valued `pushurl` yields one entry per value) — stably sorted by name; URLs are kept exactly as git prints them (they may contain spaces and are never interpreted as paths or passed back to git); parsed output is validated before it is trusted — valid UTF-8, every line must be `name<TAB>url (fetch)`, `name<TAB>url (push)` or the bare `name<TAB>` form, every name must be non-empty, free of whitespace and pass the same escape-rejecting check as status paths, and a remote may carry at most one fetch line, otherwise `InvalidData`; error behaviour matches `status`/`tags` (`NotFound`/`NotADirectory`/`Other` with git's message), and existing `status`/`diff`/`stage`/`unstage`/`commit`/`branches`/`checkout`/`restore`/`stash_push`/`stash_list`/`stash_apply`/`stash_drop`/`stash_pop`/`amend`/`log`/`tags` behaviour is unchanged
- minimal safe Git remote management (`git` module: entry points `git::add_remote(root, name, url) -> io::Result<GitRemoteSnapshot>`, `git::set_remote_url(root, name, url) -> io::Result<GitRemoteSnapshot>` and `git::remove_remote(root, name) -> io::Result<GitRemoteSnapshot>`): `add_remote` registers a new remote with `git -C <root> remote add <name> -- <url>`, `set_remote_url` rewrites an existing remote's fetch URL with `git -C <root> remote set-url <name> -- <url>` (without `--push`, so an explicit `remote.<name>.pushurl` is kept untouched), and `remove_remote` deletes a remote with `git -C <root> remote remove <name>`; each returns the fresh `GitRemoteSnapshot` from `git::remotes`. All three are strictly local — they only read or write the repository's Git configuration, never contact a network, perform a fetch or a push, or touch the worktree or the index; no shell is involved and every name and URL travels as a single argument, with the `--` separator shielding the URL of `add_remote`/`set_remote_url` from option parsing, so even a URL that starts with `-` is stored literally. Names and URLs are validated before git is spawned — a name must be non-empty, free of NUL bytes and whitespace, not `-`-prefixed, and free of `..` and of absolute or drive components; a URL must be non-empty and free of NUL bytes (spaces are allowed and stored raw) — otherwise `InvalidInput`; a name that already exists (for `add_remote`) or does not exist (for `set_remote_url`/`remove_remote`) surfaces as `Other` with git's message; error behaviour otherwise matches `remotes` (`NotFound`/`NotADirectory`/`Other`/`InvalidData`), and existing `status`/`diff`/`stage`/`unstage`/`commit`/`branches`/`checkout`/`restore`/`stash_push`/`stash_list`/`stash_apply`/`stash_drop`/`stash_pop`/`amend`/`log`/`tags`/`remotes` behaviour is unchanged
- minimal read-only Git remote lookup (`git` module: entry points `git::remote_url(root, name) -> io::Result<GitRemote>` and `git::remote_exists(root, name) -> io::Result<bool>`): both run the same strictly local `git -C <root> remote -v` query as `git::remotes` — no shell, no network access, no fetch or push — and reuse its parsing and validation; `remote_url` returns the `GitRemote` whose name matches, and a validly named remote that is not configured surfaces as `NotFound` with the name in the message (unlike `set_remote_url`/`remove_remote`, which let git report it); `remote_exists` returns `Ok(true)` exactly when the parsed snapshot contains the name and `Ok(false)` for a validly named but absent remote, while root/git-binary/git-exit/parse errors are reported exactly as `remotes`; both validate `name` before git is spawned with the same rules as the remote-management operations (empty/NUL/whitespace/`-`-prefixed/`..`/absolute-or-drive names are `InvalidInput`), and existing `status`/`diff`/`stage`/`unstage`/`commit`/`branches`/`checkout`/`restore`/`stash_push`/`stash_list`/`stash_apply`/`stash_drop`/`stash_pop`/`amend`/`log`/`tags`/`remotes`/`tag`/`delete_tag`/`add_remote`/`set_remote_url`/`remove_remote` behaviour is unchanged

- minimal, dependency-free Git status adaptation for the shell UI (`git_status` module in `nextide-shell`, a pure trait/model layer that never modifies the kernel): `status_kind` classifies a kernel `GitFileState` (`XY` columns) into a typed `StatusKind` (`Conflicted`/`StagedAndUnstaged`/`Staged`/`Unstaged`/`Untracked`/`Clean` — untracked wins over conflicts, two-sided changes beat one-sided ones, and ignored states classify as `Clean` since `status` never reports them), `tree_statuses` maps a `GitStatusSnapshot` into one `TreeStatus` per entry (path, kind, raw state, and the `original` source path for renames/copies, with `is_rename_or_copy`) re-stably-sorted by path so the model's ordering is its own contract, `summary` derives the status-bar counts (`GitStatusSummary`: total plus staged/unstaged/untracked/conflicted — two-sided entries count toward both staged and unstaged, conflicts are their own bucket, a clean snapshot is all zeros with `is_clean()`, and `From<&GitStatusSnapshot>` is provided), and `marker_for` looks up one path's marker for tree-row badges; `GitStatusAdapter` is the mapping contract with default methods delegating to the free functions, and `DefaultGitStatusAdapter` is the ready-to-use unit implementation; no new dependencies and existing shell behaviour (DesktopShell, renderer, view model, events) is unchanged

Task state and summary APIs are available through `TaskManager::state`, `summary`, `summaries`, and `ids`; pending tasks can be removed and terminal tasks can be cleaned with lifecycle events.

Capability metadata is observable through `CapabilityRegistry::ids`, `iter`, `summary`, and `summaries`: iteration and projections are returned in stable, sorted id order, and `CapabilitySummary` is a cloneable, UI-safe snapshot of a capability's id, version, and declared permissions. `is_empty`/`len`/`contains` remain available for cheap registry checks.

Shell command metadata is observable through `command_ids`, `get_command`, `command_summary`, and `command_summaries`: ids enumerate in stable declaration order, and `CommandSummary` is a cloneable, UI-safe snapshot of a command's id, title, and search keywords, decoupled from the static `COMMANDS` descriptor table so the command palette, UI, and plugins can observe commands without borrowing. `search_commands`/`command_id`/`COMMANDS` remain unchanged.

Shell command execution is observable through `CommandExecutionResult`, `CommandOutcome`, and `CommandError`: `DesktopShell::execute_observed` runs a `ShellCommand` and returns a typed, cloneable record (stable command id, tri-state outcome, structured error) that UI and plugins can consume without borrowing. Every execution publishes a `shell.command.executed` event with a stable payload (`id=<id>,outcome=<outcome>` or `id=<id>,outcome=failed,error=<kind>,message=<message>`); failures keep publishing `shell.command.failed` plus an error notification. `command_title`, `is_registered`, and `describe_execution` resolve execution results back to registered command metadata, and `CommandError`/`CommandErrorKind` classify failures (`io`, `not-found`, `invalid-state`, `unknown`) with a message, round-tripping through `std::io::Error`. Existing `execute`, `execute_checked`, `execute_selected`, and `CommandResult` signatures and behavior are unchanged; the checked/selected paths now route through the observable one, so every executed command also emits `shell.command.executed`.

## Development

```powershell
cargo test --workspace
cargo run -p nextide-cli -- smoke
cargo run -p nextide-cli -- bootstrap
cargo run -p nextide-cli -- task-smoke
```

`task-smoke` exercises the background task runtime: it registers a cross-platform echo command (`cmd.exe /C echo` on Windows, `sh -c printf` elsewhere), spawns it through `TaskManager::spawn_async`, polls `AsyncTaskHandle::wait_timeout` within a finite deadline, and prints the task's status and output, panicking on failure or timeout.

Background async tasks can also be bridged to a caller-owned `EventBus`: `TaskManager::spawn_async_with_sink` / `spawn_async_timeout_with_sink` accept an `AsyncTaskEventSink`, and the UI thread polls the matching `TaskEventReceiver` (e.g. each frame) and replays what it consumed into the `EventBus` with `publish_into` — so the background worker never holds the non-thread-safe bus, while the async task's lifecycle and output still surface as `task.*` events.

The editor kernel is the single source of truth for document mutations. UI, AI, collaboration, and extensions must eventually submit changes through the same transaction API.
